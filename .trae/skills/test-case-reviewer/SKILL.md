# Test Case Reviewer - 测试用例评审技能

## 角色定位

你将扮演三个角色进行测试用例评审：

### 1. 产品经理（PM）视角
- 关注需求覆盖完整性
- 验证业务场景是否全面
- 检查用户价值体现

### 2. 测试经理视角
- 关注测试设计质量
- 验证用例可执行性
- 检查测试数据充分性

### 3. 研发工程师视角
- 关注技术实现可行性
- 验证边界条件合理性
- 检查异常场景覆盖

## 核心任务

基于PRD文档和测试用例Excel，生成多角色评审报告，包含：
1. 覆盖度分析
2. 质量评估
3. 问题识别
4. 改进建议
5. 风险预警

## 执行流程

### 1. 文档准备
```
1.1 读取PRD文档
1.2 读取测试用例Excel
1.3 建立需求-用例映射
1.4 识别评审范围
```

### 2. 多角色评审
```
2.1 PM视角评审
    - 需求覆盖检查
    - 业务场景验证
    - 用户价值评估

2.2 测试经理视角评审
    - 用例设计质量
    - 测试数据充分性
    - 可执行性评估

2.3 研发视角评审
    - 技术可行性
    - 边界条件合理性
    - 异常场景覆盖
```

### 3. 问题汇总
```
3.1 分类整理问题
3.2 评估问题严重程度
3.3 提出改进建议
3.4 识别潜在风险
```

### 4. 报告生成
```
4.1 编写评审摘要
4.2 详细问题列表
4.3 改进建议清单
4.4 风险预警
4.5 评审结论
```

## 评审检查清单

### PM视角检查项

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 需求覆盖度 | 30% | 所有需求点都有对应用例 |
| 业务场景完整性 | 25% | 覆盖正常/异常/边界场景 |
| 用户价值体现 | 20% | 用例体现用户实际使用场景 |
| 流程覆盖 | 15% | 主流程和分支流程都有覆盖 |
| 优先级合理性 | 10% | 高优先级功能用例密度高 |

### 测试经理视角检查项

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 用例可执行性 | 25% | 步骤清晰，数据明确 |
| 测试数据充分性 | 25% | 覆盖有效/无效/边界数据 |
| 预期结果可验证 | 20% | 结果描述具体可判断 |
| 用例独立性 | 15% | 用例间无强依赖 |
| 维护性 | 15% | 结构清晰，便于维护 |

### 研发视角检查项

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 技术可行性 | 30% | 用例在技术上可执行 |
| 边界条件合理性 | 25% | 边界值符合技术约束 |
| 异常场景覆盖 | 25% | 覆盖常见异常情况 |
| 数据构造难度 | 10% | 测试数据易于准备 |
| 自动化可行性 | 10% | 适合自动化的用例已标记 |

## 问题分级标准

| 级别 | 定义 | 处理要求 |
|------|------|----------|
| 严重 | 需求遗漏、核心功能未覆盖 | 必须修复 |
| 高 | 重要场景缺失、用例不可执行 | 建议修复 |
| 中 | 数据不充分、描述不清晰 | 可选修复 |
| 低 | 格式问题、优化建议 | 参考处理 |

## 评分标准

### 综合评分计算

```
综合评分 = PM评分 × 30% + 测试经理评分 × 40% + 研发评分 × 30%

评分等级：
- 优秀：90-100分
- 良好：80-89分
- 合格：70-79分
- 不合格：<70分
```

### 各维度评分表

| 维度 | 优秀(90-100) | 良好(80-89) | 合格(70-79) | 不合格(<70) |
|------|-------------|------------|------------|------------|
| 覆盖度 | ≥95% | 85-94% | 75-84% | <75% |
| 质量 | 无严重问题 | 1-2个高优先级 | 3-5个高优先级 | >5个高优先级 |
| 可执行性 | 100%可执行 | 90-99%可执行 | 80-89%可执行 | <80%可执行 |

## 输出规范

1. **文档格式**：Markdown
2. **输出位置**：test-output/docs/评审报告.md
3. **详细程度**：每个问题都要有具体位置和改进建议
4. **可追溯性**：问题要关联到具体用例ID

## 质量标准

- 评审覆盖率100%（所有用例都被评审）
- 问题识别准确率≥90%
- 建议可行性≥80%
- 报告结构清晰，结论明确

## 注意事项

1. **客观公正**：基于事实评审，不带主观偏见
2. **建设性**：问题要有改进建议
3. **优先级**：按严重程度排序问题
4. **可追溯**：问题要定位到具体用例

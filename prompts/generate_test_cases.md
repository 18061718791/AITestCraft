### 输出要求

请根据上述测试点，输出结构化的测试用例，格式为 JSON 数组，示例如下：
- 语言应清晰简洁，避免冗长重复；
- 请保证输出为**严格有效的 JSON 格式**，确保可以被自动解析与导出；
- 请确保每个测试用例都能独立执行，避免相互依赖；
- 请使用简体中文输出；
- 每个测试用例应包含以下内容：
  - **number**：测试用例编号（字符串格式，如 "Test0001"）
  - **system**：测试用例所属的系统名称
  - **module**：简洁且准确的功能模块名称
  - **scenario**：具体的功能场景名称
  - **title**：简洁明了的测试用例标题
  - **description**：对测试目的或覆盖点的简要描述
  - **precondition**：测试执行前的前置条件
  - **steps**：每条用户操作步骤（字符串数组）
  - **expected_results**：每条步骤对应的预期结果（字符串数组），**必须与 steps 一一对应，数量相同**
  - **actual_result**：测试执行时的实际观察结果，默认填写 "待测试"
  - **pass_fail**：是否通过，默认填写 "待测试"

### 输出格式
```json
[
  {
    "number": "Test0001",
    "system": "{system}",
    "module": "{module}",
    "scenario": "{scenario}",
    "title": "邮箱密码正确时登录成功",
    "description": "验证邮箱和密码输入正确后可登录系统",
    "precondition": "已打开登录页面",
    "steps": [
      "输入正确邮箱地址",
      "输入正确密码",
      "点击登录按钮"
    ],
    "expected_results": [
      "邮箱输入框显示输入的邮箱地址",
      "密码输入框显示掩码字符",
      "成功跳转到系统首页"
    ],
    "actual_result": "待测试",
    "pass_fail": "待测试"
  },
  {
    "number": "Test0002",
    "system": "{system}",
    "module": "{module}",
    "scenario": "{scenario}",
    "title": "邮箱密码超长给出友好提示",
    "description": "邮箱和密码输入长度超长时给出友好提示",
    "precondition": "已打开登录页面",
    "steps": [
      "输入17位的邮箱地址",
      "输入17位的密码",
      "点击登录按钮"
    ],
    "expected_results": [
      "邮箱输入框显示输入的17位邮箱地址",
      "密码输入框显示掩码字符",
      "页面提示'邮箱地址超长，请重新输入'和'密码超长，请重新输入'"
    ],
    "actual_result": "待测试",
    "pass_fail": "待测试"
  }
]
```

**重要规则：**
1. **steps 和 expected_results 必须是相同长度的字符串数组**
2. **expected_results[i] 对应 steps[i] 的预期结果**，即第 i 个步骤执行后应该出现的结果
3. 如果多个步骤共同产生一个最终结果，请将最终结果放在最后一个步骤对应的 expected_results 中，前面的步骤对应中间状态或界面反馈
4. 每个步骤的预期结果应该具体、可验证，描述执行该步骤后界面或系统的具体变化

请直接输出 JSON 数组，不要包含任何其他说明文字或 markdown 标记。

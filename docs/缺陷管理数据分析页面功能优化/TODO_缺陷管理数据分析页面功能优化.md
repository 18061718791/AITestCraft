## 3. 已知问题

### 3.1 递归查询性能
**问题描述**: 递归查询所有子目录ID可能会影响性能，特别是在目录结构较深的情况下。

**解决方案**:
- 使用缓存机制，减少数据库查询次数
- 考虑使用数据库的递归查询功能（如 PostgreSQL 的 WITH RECURSIVE）
- 考虑使用物化视图或预计算子目录ID

**优先级**: 中

### 3.2 节点名称映射
**问题描述**: 节点名称映射在 `DefectTree` 组件中构建，如果目录结构较大，可能会影响性能。

**解决方案**:
- 考虑使用 memo 优化节点名称映射的构建
- 考虑使用 useCallback 优化回调函数的性能

**优先级**: 低

## 5. 操作指引

### 5.1 测试项目管理根节点
1. 打开数据分析页面
2. 点击目录树中的"项目管理"根节点
3. 验证右侧显示提示信息，而不是统计数据

### 5.2 测试数据统计范围
1. 打开数据分析页面
2. 点击目录树中的"智能物联"项目节点
3. 验证趋势图和饼图展示该项目下所有子节点的数据汇总
4. 点击目录树中的"低代码系统"节点
5. 验证趋势图和饼图展示该系统下所有子节点的数据汇总

### 5.3 测试折线图标题
1. 打开数据分析页面
2. 点击目录树中的任意节点
3. 验证折线图标题显示该节点的名称

### 5.4 监控性能
1. 打开浏览器开发者工具
2. 切换到 Performance 标签
3. 点击目录树中的节点
4. 验证数据查询和页面渲染的性能
5. 如果性能不佳，考虑使用缓存或优化查询

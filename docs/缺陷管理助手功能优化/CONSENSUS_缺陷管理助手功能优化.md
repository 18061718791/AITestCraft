# 缺陷管理助手功能优化 - 共识文档

## 1. 明确的需求描述和验收标准

### 1.1 需求1：问题趋势分析默认展示全部数据

**需求描述**:
当用户明确想要查看问题趋势分析时，系统应该默认展示全部时间范围的数据，不再弹出时间范围选择框。

**涉及场景**:
1. 用户直接输入"查看XXX的问题趋势分析"，直接根据用户意图展示全部数据
2. 用户在弹出的选项中选择了"问题趋势分析"，直接展示全部数据

**验收标准**:
- [ ] 用户输入"查看智能物联项目的问题趋势分析"时，直接展示全部数据的趋势分析图表
- [ ] 用户在选项中选择"问题趋势分析"时，直接展示全部数据的趋势分析图表
- [ ] 不再弹出时间范围选择框（上周、上个月、过去三个月、全部数据）
- [ ] 问题列表功能不受影响，仍然需要选择时间范围

### 1.2 需求2：去除模块数据统计

**需求描述**:
在查看某个项目的问题趋势分析时，如果某个系统下包含模块，不应该将模块也作为问题数据统计进去。只统计系统（level=1）的数据，不统计模块（level=2）的数据。

**示例**:
- 智能物联项目（level=0）
  - 低代码系统（level=1，ID=2981）
    - 低代码工具（level=2）
    - 研发管理平台（level=2）
    - 客户问题（level=2）
  - 物联平台（level=1，ID=2983）

在问题趋势分析时，应该只统计低代码系统和物联平台的数据，不统计低代码工具、研发管理平台、客户问题的数据。

**验收标准**:
- [ ] 查看智能物联项目的问题趋势分析时，系统分布图只显示"低代码系统"和"物联平台"
- [ ] 不显示"低代码工具"、"研发管理平台"、"客户问题"等模块
- [ ] 问题列表功能不受影响，仍然可以查看模块级别的问题

### 1.3 需求3：用户体验优化

**需求描述**:
用户在点击系统弹出的选项时，虽然前端已经表示成功，但后台没反应过来，导致后端直接返回不支持的消息。需要提供更好的用户体验。

**验收标准**:
- [ ] 用户点击选项后，后端能够正确识别并处理请求
- [ ] 如果后端无法处理，提供更友好的错误提示
- [ ] 前端和后端的参数传递保持一致

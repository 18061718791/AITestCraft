## 二、详细改进说明

### 2.1 完善否定语义识别

#### 支持的模式

| 模式类型 | 示例 | 说明 |
|---------|------|------|
| `除...外` | "除已关闭外" | 排除单个状态 |
| `除了...` | "除了已关闭和已解决的" | 排除多个状态 |
| `不包括` | "不包括已关闭的" | 否定包含 |
| `不包含` | "不包含紧急的" | 否定包含 |
| `非` | "非已关闭状态" | 否定判断 |
| `排除` | "排除已关闭的" | 主动排除 |
| `不要` | "不要已关闭的" | 否定意愿 |
| `不是` | "不是已关闭的" | 否定判断 |
| `未` | "未关闭的" | 否定完成 |
| `没` | "没解决的" | 否定完成 |

#### 代码实现
```typescript
// EntityExtractor.ts
private extractNegativeStatus(query: string, params: QueryParams): void {
  // 多状态排除
  const multiExcludePattern = /(?:除|除了|除去|排除)(.+?)(?:和|与|、|,)(.+?)(?:外|的|问题|$)/;
  
  // 单状态否定模式
  const negativePatterns = [
    { pattern: /除(.+?)外/, type: 'exclude' },
    { pattern: /不包括(.+?)(?:的|问题|$)/, type: 'exclude' },
    { pattern: /不要(.+?)(?:的|问题|$)/, type: 'exclude' },
    // ... 更多模式
  ];
}
```

#### 测试用例
```
✓ "查看除已关闭外的问题" → excludeStatusName: '已关闭'
✓ "除了已关闭和已解决的问题" → excludeStatusNames: ['已关闭', '已解决']
✓ "不要紧急优先级的问题" → excludePriorityName: '紧急'
✓ "未关闭的问题" → excludeStatusName: '已关闭'
```

### 2.2 实体冲突检测

#### 检测的冲突类型

1. **状态冲突**
   - 同时要求某状态和排除该状态
   - 示例："查看已关闭的问题，不要已关闭的"

2. **优先级冲突**
   - 同时要求某优先级和排除该优先级
   - 示例："查看紧急的问题，排除紧急的"

3. **时间范围冲突**
   - 同时包含多个时间范围
   - 示例："查看今天和昨天的问题"

4. **列表冲突**
   - 状态在排除列表中
   - 示例：要求"新建"状态但排除列表包含"新建"

#### 代码实现
```typescript
// EntityExtractor.ts
private detectConflicts(params: QueryParams, query: string): void {
  const conflicts: string[] = [];

  // 1. 检查状态和排除状态冲突
  if (params.statusName && params.excludeStatusName) {
    if (params.statusName === params.excludeStatusName) {
      conflicts.push(`查询条件矛盾：同时要求"${params.statusName}"和"排除${params.excludeStatusName}"`);
    }
  }

  // 2. 检查状态和排除状态列表冲突
  if (params.statusName && params.excludeStatusNames) {
    if (params.excludeStatusNames.includes(params.statusName)) {
      conflicts.push(`查询条件矛盾：要求"${params.statusName}"状态但又在排除列表中`);
    }
  }

  // 更多检测...

  if (conflicts.length > 0) {
    params.hasConflict = true;
    params.conflictMessages = conflicts;
  }
}
```

#### 用户提示
当检测到冲突时，系统会在响应消息中添加警告：
```
已为您找到智能物联项目的问题列表...

⚠️ 注意：查询条件矛盾：同时要求"已关闭"和"排除已关闭"
```

### 2.3 组合条件支持

#### 支持的组合类型

| 组合类型 | 连接词 | 示例 |
|---------|--------|------|
| 状态OR | 或、和、与、、 | "状态为新建或进行中" |
| 优先级OR | 或、和、与、、 | "紧急或高优先级" |
| 多状态 | 数组 | statusNames: ['新建', '进行中'] |
| 多优先级 | 数组 | priorityNames: ['紧急', '高'] |

#### 代码实现
```typescript
// EntityExtractor.ts
private extractCombinedStatus(query: string, params: QueryParams): void {
  const combinedPatterns = [
    /状态[为是](.+?)(?:或|和|与|、|,)(.+?)(?:的|问题|$)/,
    /(.+?)(?:或|和|与|、|,)(.+?)状态/,
  ];
  
  for (const pattern of combinedPatterns) {
    const match = query.match(pattern);
    if (match && match[1] && match[2]) {
      const statuses: string[] = [];
      // 提取多个状态...
      if (statuses.length > 1) {
        params.statusNames = statuses;
        params.statusName = statuses[0] || '';
      }
    }
  }
}
```

#### SQL生成
```typescript
// QueryExecutor.ts
// 组合状态使用 ANY
if (params.statusNames && params.statusNames.length > 1) {
  whereClause += ` AND i.status_id = ANY($${queryParams.length + 1})`;
  queryParams.push(statusIds);
}

// 多状态排除使用 ALL
if (params.excludeStatusNames && params.excludeStatusNames.length > 0) {
  whereClause += ` AND i.status_id != ALL($${queryParams.length + 1})`;
  queryParams.push(excludeStatusIds);
}
```

#### 测试用例
```
✓ "状态为新建或进行中" → statusNames: ['新建', '进行中']
✓ "紧急或高优先级" → priorityNames: ['紧急', '高']
✓ "除了已关闭和已解决的" → excludeStatusNames: ['已关闭', '已解决']
```

# 缺陷管理助手优化实施计划

## 项目分析

通过对当前系统的分析，我发现以下问题：

1. **自然语言识别准确率低**：
   - 提示词模板不够精确，缺乏缺陷管理领域的示例
   - 单一依赖LLM识别，缺乏规则匹配
   - 没有考虑对话上下文

2. **缺乏意图置信度评估**：
   - 系统已经计算置信度，但没有根据置信度主动澄清用户意图

3. **缺乏上下文理解**：
   - 每次查询都是独立处理，没有维护对话历史

4. **错误处理不够友好**：
   - 错误提示不够具体，缺乏备选方案建议

## 技术方案

### 1. 优化提示词模板

**当前实现**：
- 提示词模板位于`LLMIntentParser.ts`的`buildPrompt`方法
- 要求模型从支持的意图列表中选择意图
- 提取实体包括systemId, system, statusId, status, priorityId, priority等

**优化方案**：
- 添加更多缺陷管理领域的示例
- 提供具体的系统和模块名称示例
- 改进提示词结构，使其更精确地指导模型

### 2. 添加意图置信度

**当前实现**：
- 系统已经计算置信度，但没有使用它来主动澄清用户意图
- 当意图为'unknown'时，直接返回"暂不支持"的提示

**优化方案**：
- 添加置信度阈值配置（默认0.7）
- 当置信度低于阈值时，返回意图澄清提示
- 实现意图澄清的处理逻辑

### 3. 实现上下文记忆

**当前实现**：
- 每次查询都是独立处理，没有维护对话历史
- 前端和后端都没有上下文管理

**优化方案**：
- 前端：维护对话历史，在API请求中发送上下文信息
- 后端：接收并处理上下文信息，在意图识别中考虑对话历史
- 优化提示词模板，使其能够利用上下文信息

### 4. 优化错误处理

**当前实现**：
- 错误处理比较简单，直接返回错误消息
- 没有提供备选方案建议

**优化方案**：
- 设计友好的错误提示模板
- 实现错误分类和处理逻辑
- 为常见错误提供备选方案建议

# CONSENSUS - AITestCraft 功能测试共识文档

## 1. 明确需求描述

### 1.1 项目目标

对AITestCraft平台进行全面功能测试，通过三个阶段的协作，产出：
1. 专业的产品需求文档（PRD）
2. 详细的测试用例文档（Excel格式）
3. 多角色评审报告

### 1.2 功能模块清单

| 模块ID | 模块名称 | 优先级 | 复杂度 |
|--------|----------|--------|--------|
| M01 | 测试用例管理 | P0 | 高 |
| M02 | 缺陷管理 | P0 | 高 |
| M03 | 缺陷管理助手 | P0 | 高 |
| M04 | 项目管理 | P1 | 中 |
| M05 | 系统配置 | P1 | 中 |
| M06 | 消息通知 | P1 | 低 |
| M07 | 快捷键管理 | P2 | 低 |
| M08 | Prompt管理 | P2 | 低 |

## 2. 技术实现方案

### 2.1 技能架构设计

创建三个标准化技能，每个技能负责一个阶段的任务：

```
.trae/skills/
├── prd-analyzer/          # 产品经理分析技能
│   └── SKILL.md
├── test-case-generator/   # 测试用例生成技能
│   └── SKILL.md
└── test-case-reviewer/    # 测试用例评审技能
    └── SKILL.md
```

### 2.2 技术约束

| 约束项 | 要求 |
|--------|------|
| 代码修改 | 禁止修改任何项目源代码 |
| 输出位置 | 所有输出存储在 test-output/ 目录 |
| Excel生成 | 使用 exceljs 库 |
| 文档格式 | Markdown + Excel |
| 技能格式 | 遵循 SKILL.md 规范 |

### 2.3 集成方案

1. **阶段1 → 阶段2**：PRD文档作为测试用例生成的输入
2. **阶段2 → 阶段3**：测试用例Excel作为评审的输入
3. **技能复用**：通过 .trae/skills/ 目录实现后续复用

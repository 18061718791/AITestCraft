# 缺陷管理助手功能优化 - 对齐文档

## 1. 项目上下文分析

### 1.1 项目结构
- **后端技术栈**: TypeScript, Node.js, Prisma ORM, MySQL
- **前端技术栈**: React, TypeScript, Ant Design, Chart.js
- **核心服务**:
  - IntelligentQAService: 智能问答服务，处理用户意图识别和响应
  - StatisticsService: 统计服务，提供趋势分析和分布数据
  - ListService: 列表服务，处理缺陷列表查询
  - IntentRecognizer: 意图识别器，使用规则和LLM融合策略

### 1.2 目录层级结构
根据 `schema.prisma` 和代码分析：
- **level 0**: 项目节点（如：智能物联项目，ID=2980）
- **level 1**: 系统节点（如：低代码系统，ID=2981；物联平台，ID=2983）
- **level 2**: 模块节点（如：低代码工具、研发管理平台、客户问题）

### 1.3 现有代码模式
- **意图识别**: 使用规则匹配 + LLM融合策略
- **槽位填充**: SlotFiller + LLM实体提取
- **上下文管理**: ContextManager管理对话上下文
- **缓存机制**: 使用Map实现TTL缓存

## 2. 需求理解确认

### 2.1 原始需求
用户提出了三个优化点：

**需求1**: 问题趋势分析默认展示全部数据
- 场景1：用户直接输入"查看XXX的问题趋势分析"，直接展示全部数据，不再弹出时间选择
- 场景2：用户在弹出的选项中选择了"问题趋势分析"，直接展示全部数据，不再弹出时间选择

**需求2**: 去除模块数据统计
- 问题：在查看某个项目的问题趋势分析时，系统下包含的模块也被统计进去了
- 示例：智能物联项目，低代码系统下包含低代码工具、研发管理平台和客户问题三个模块，需要去除这三条数据
- 理论上：只统计系统（level=1）的数据，不统计模块（level=2）的数据

**需求3**: 用户体验优化
- 问题：用户点击系统弹出的选项时，前端显示成功但后端返回不支持的消息
- 需要提供更好的体验方案

### 2.2 边界确认
- **任务范围**: 仅针对缺陷管理助手的功能优化
- **不涉及**: 其他模块的修改、数据库结构变更
- **影响范围**:
  - 后端：IntelligentQAService.ts, StatisticsService.ts, ListService.ts
  - 前端：IntelligentQAPage.tsx

### 2.3 需求理解
基于代码分析，我理解：

**需求1实现方案**:
- 当用户意图明确为"问题趋势分析"时，设置 `timeRange: 'all'` 和 `timeRangeExplicit: true`
- 在 `IntelligentQAService.ts` 中修改逻辑，跳过时间范围选择步骤

**需求2实现方案**:
- 在 `StatisticsService.ts` 的 `getSystemTrend` 和 `getSystemDistribution` 方法中
- 修改 `getAllChildDirectoryIds` 或创建新方法，只获取 level=1 的目录（系统）
- 在 `ListService.ts` 的 `getParentIds` 方法中，对于趋势分析场景，只返回 level=1 的目录

**需求3实现方案**:
- 分析前端 `handleChoice` 方法的逻辑
- 确保前端发送的请求包含正确的参数
- 在后端添加更友好的错误处理和提示

## 3. 疑问澄清

### 3.1 需求1的细节
- **问题**: 用户说"默认展示全部数据"，是指时间范围为"全部"还是指所有项目的数据？
- **理解**: 应该是指时间范围为"全部"，即从最早记录到现在的所有数据

### 3.2 需求2的细节
- **问题**: 是否只针对问题趋势分析，还是包括问题列表？
- **理解**: 根据需求描述"在查看某个项目的问题趋势分析的时候"，应该只针对趋势分析
- **确认**: 需求2只影响趋势分析，不影响问题列表

### 3.3 需求3的细节
- **问题**: 具体是什么情况下会出现"后端返回不支持的消息"？
- **分析**: 可能是用户点击选项后，后端意图识别失败返回 `unknown` 意图
- **解决方案**: 需要确保前端传递正确的 `choice` 和 `entities` 参数

## 4. 智能决策策略

### 4.1 需求1决策
- **方案**: 修改 `IntelligentQAService.ts`，当用户选择"问题趋势分析"时，直接设置 `timeRange: 'all'`
- **实现位置**: IntelligentQAService.ts 第410-506行
- **影响**: 不会影响其他功能，只改变趋势分析的默认行为

### 4.2 需求2决策
- **方案**: 修改 `StatisticsService.ts` 的 `getAllChildDirectoryIds` 方法，添加参数控制是否包含level=2的目录
- **实现位置**:
  - StatisticsService.ts 第31-48行：修改 `getAllChildDirectoryIds` 方法
  - StatisticsService.ts 第196行：调用时传入参数
- **影响**: 只影响趋势分析，不影响问题列表

### 4.3 需求3决策
- **方案**: 分析前端 `handleChoice` 逻辑，确保参数传递正确；在后端添加更详细的日志和错误提示
- **实现位置**:
  - 前端：IntelligentQAPage.tsx 第228-338行
  - 后端：IntelligentQAService.ts 第229-338行
- **影响**: 提升用户体验，不会改变功能逻辑

# 缺陷管理数据分析页面功能优化 - ALIGNMENT

## 1. 项目上下文分析

### 1.1 现有项目结构
- **前端技术栈**: React + TypeScript + Ant Design
- **后端技术栈**: Node.js + Express + Prisma + PostgreSQL
- **数据分析页面**: `frontend/src/pages/defect/DefectAnalysisPage.tsx`
- **统计服务**: `backend/src/services/statisticsService.ts`
- **目录树服务**: `backend/src/services/treeService.ts`

### 1.2 现有代码模式
- 数据获取通过 `defectApi` 调用后端接口
- 图表组件接收 `systemId` 参数获取对应节点的统计数据
- 目录树通过 `DefectTree` 组件展示，节点选择通过 `onNodeSelect` 回调传递

### 1.3 数据模型
- **issues表**: 存储缺陷问题数据，包含 `parent_id` 字段关联目录
- **directories表**: 存储目录结构，包含 `parent_id` 和 `project_id` 字段
- **projects表**: 存储项目信息

## 2. 原始需求

用户报告了数据分析页面的三个问题：

1. **数据统计范围问题**: 选择项目（如智能物联）或系统（如低代码系统）时，右侧分析维度展示的数据不是该项目/系统下所有子目录节点汇总数据的统计，而是从某个固定日期（2026年2月9日）作为起点的数据统计

2. **折线图标题显示问题**: 点击低代码工具模块时，右侧分析维度的折线图标题显示为"大数据平台"，而不是对应模块的名称

3. **项目管理节点不应展示数据**: 点击项目管理（根节点）时，右侧不应该展示任何统计数据，因为项目管理只是维护多个项目的根节点

## 3. 边界确认

### 3.1 任务范围
- 修复数据统计范围问题，确保选择项目/系统时统计所有子节点的数据
- 修复折线图标题显示问题，动态获取节点名称
- 添加项目管理根节点的特殊处理，不展示统计数据

### 3.2 任务限制
- 不修改数据库结构
- 不改变现有的API接口设计
- 保持现有的图表展示方式

## 4. 需求理解

### 4.1 问题1：数据统计范围问题

**现状分析**:
- 在 `statisticsService.ts` 的 `getSystemTrend` 方法中，使用 `systemFilter = AND parent_id = '${parentId}'` 查询数据
- 这只会查询直接子节点的问题，不会递归查询所有子节点的问题
- `getEarliestRecordDate(parentId)` 计算起始日期时，也只考虑直接子节点

**期望行为**:
- 选择项目节点（如智能物联 2980）时，应该统计该项目下所有子节点的数据
- 选择系统节点（如低代码系统）时，应该统计该系统下所有子目录节点汇总数据的统计

### 4.2 问题2：折线图标题显示问题

**现状分析**:
- 在 `TrendChart.tsx` 中，标题通过硬编码的ID映射生成：
  ```typescript
  text: systemId ? `${systemId === 2981 ? '低代码&研发管理平台' : systemId === 2982 ? '物联应用' : systemId === 2983 ? '物联平台' : '大数据平台'} ...`
  ```
- 这种方式不够灵活，无法动态获取节点名称

**期望行为**:
- 折线图标题应该动态显示选中节点的名称，而不是硬编码的ID映射

### 4.3 问题3：项目管理节点不应展示数据

**现状分析**:
- 在 `DefectAnalysisPage.tsx` 中，`shouldShowSystemDistribution = selectedNodeId === 2980` 只对特定节点ID生效
- 当选择项目管理根节点（ID: 0）时，仍然会展示统计数据

**期望行为**:
- 点击项目管理根节点（ID: 0）时，右侧不应该展示任何统计数据
- 应该显示提示信息，说明项目管理节点不展示统计数据

## 5. 疑问澄清

### 5.1 需要确认的问题

1. **数据统计范围的实现方式**:
   - 是否需要递归查询所有子节点的问题数据？
   - 还是需要修改目录结构，让每个节点都包含其所有子节点的问题汇总？

2. **项目管理根节点的ID**:
   - 项目管理根节点的ID是固定的0吗？
   - 还是需要动态判断是否为根节点？

3. **折线图标题的获取方式**:
   - 是否需要从目录树数据中获取节点名称？
   - 还是需要新增一个API接口获取节点名称？

### 5.2 基于现有代码的决策

**决策1：数据统计范围的实现方式**
- 递归查询所有子节点的问题数据
- 在 `statisticsService.ts` 中新增一个方法 `getAllChildDirectoryIds`，递归获取所有子目录ID
- 在查询数据时，使用 `IN` 子句查询所有子节点的问题

**决策2：项目管理根节点的ID**
- 项目管理根节点的ID是固定的0
- 在 `DefectAnalysisPage.tsx` 中，判断 `selectedNodeId === 0` 时，不展示统计数据

**决策3：折线图标题的获取方式**
- 从目录树数据中获取节点名称
- 在 `DefectTree` 组件中，新增一个回调 `onNodeNameChange`，传递选中节点的名称
- 在 `DefectAnalysisPage` 中，维护一个 `selectedNodeName` 状态，传递给 `TrendChart` 组件
